Key Constraints & Gotchas

  • No month filter on /api/inventory — inventory has no time dimension; only warehouse & category apply
  • /api/demand and /api/backlog accept no query filters — data is always returned in full
  • In-memory mutations reset on restart — purchase orders and tasks created via POST are lost when the server stops
  • Revenue targets — $800K/month for a single month selection; $9.6M YTD when all months are selected
  • Backlog has_purchase_order flag — computed at request time by cross-referencing purchase_orders in memory, not stored in JSON
  • Filter sentinel value — all filter params treat the string "all" as "no filter applied"; this convention is shared by both frontend and backend
  • Date format — all dates use ISO 8601; month filter uses YYYY-MM prefix matching or quarter strings Q1-2025 … Q4-2025
  • i18n — English and Japanese supported; locale state is in useI18n.js; user profile data in useAuth.js is locale-aware
